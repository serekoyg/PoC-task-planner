# 코드 구조와 상태 변경 규칙

서버나 전역 상태 라이브러리 없이 `App`이 소유한 React 상태를 화면에 전달합니다. 새 추상화는 반복되는 데이터 변경과 순수 계산에 한정합니다.

## 책임 구분

| 위치 | 책임 |
| --- | --- |
| `src/App.tsx` | 화면 경로, 사이드바·검색·알림 등 앱 외곽 UI, 개인·모임 계획과 활동 기록의 연결 |
| `src/routes/PlannerRoutes.tsx` | URL 매개변수로 대상 계획·모임을 찾아 화면에 전달 |
| `src/hooks/usePersonalPlans.ts` | 개인 할 일·일정·목록·휴지통과 목록별 표시 설정 |
| `src/hooks/useStudyRooms.ts` | 모임 상태, 가입 요청·생성, 공개 범위, 공동 계획 변경 |
| `src/hooks/useFocusSessions.ts` | 활동 명령, 중복 종료 방지, 완료 시간 누적, 실행 중 타이머 |
| `src/hooks/useStoredState.ts` | JSON 상태 저장 효과의 공통 처리 |
| `src/lib/plannerStorage.ts` | 기존 저장 키, 초기 데이터 읽기, 이전 데이터 정규화 |
| `src/lib/focus.ts` | 시작·재시작·일시정지·종료의 순수 변환과 시간 계산 |
| `src/lib/studyPlans.ts` | 멤버별 완료·참여 상태와 편집 권한의 공통 규칙 |
| `src/lib/calendarTime.ts`, `src/lib/color.ts` | 화면과 분리된 날짜·시간 및 색상 계산 |
| `src/pages`, `src/components` | 화면별 선택·입력 상태와 표시·상호작용 |

## 유지해야 하는 동작

- 기존 `haru.v2.*`, `haru.demo-*` 저장 키와 데이터 형식을 유지합니다. 별도 데이터 초기화나 마이그레이션은 필요 없습니다.
- 상세 패널의 선택 상태에는 ID만 저장하고 원본 데이터에서 현재 항목을 찾습니다. 입력 중인 제목·메모는 편집기 로컬 초안이고, 완료 상태는 원본 데이터입니다. 완료 체크가 입력 중인 초안을 초기화하면 안 됩니다.
- 실행 중이거나 일시정지 중인 할 일을 완료하면 해당 활동을 종료합니다. 활동이 없다면 완료 상태만 바꿉니다. 활동 종료와 완료 토글을 동시에 호출하지 않습니다.
- 공동 할 일의 완료·완료 시각은 멤버별입니다. 다른 멤버의 기록을 변경하지 않습니다. 공동 일정의 참여 여부는 완료와 별개이며 활동을 마쳐도 바꾸지 않습니다.
- 활동 재개는 같은 기록에 구간을 추가합니다. 일시정지 시간은 누적하지 않습니다. `처음부터 시작`은 선택한 대상의 기존 활동 기록과 개인 누적 결과를 초기화하는 기존 동작을 유지합니다.
- 공동 활동의 대상은 `sourceType + sourceId + roomId`로 구분합니다. 같은 ID를 쓰는 다른 모임의 기록을 재개하거나 초기화하지 않습니다.
- `useFocusSessions`의 모든 기록 변경은 `updateRecords`를 통합니다. 이벤트 처리 중 최신 기록을 함께 갱신해 한 렌더 사이에 종료 명령이 반복되어도 한 번만 누적합니다. React 상태 갱신 함수 내부에서 다른 상태를 변경하지 않습니다.
- 목록 이름 변경·삭제는 할 일, 일정, 휴지통에 함께 반영합니다. 삭제한 목록의 계획은 기존처럼 미분류로 옮깁니다.

## 검증

`node --test tests/planner.test.mjs`는 순수 로직 22개를 검증합니다. 활동 상태 전이·중복 명령·구버전 기록·동시 집중 시간, 멤버별 완료와 일정 참여 구분, 모임 간 분리, 날짜 경계 이동, 색상 변환, 저장 데이터 호환성을 다룹니다. 테스트용 Vite 캐시는 개발 서버와 분리하며 네트워크 포트를 사용하지 않습니다.

주요 수동 회귀 확인:

1. `/todos`에서 모임 제목을 누르면 URL을 유지한 채 상세 패널이 열리는지 확인합니다.
2. 개인·모임 활동 시작 → 일시정지 → 상세 패널 체크 → 완료 취소를 확인합니다.
3. 개인 집중 화면에서 일시정지 후 마치면 일시정지 전 시간으로 완료되는지 확인합니다.
4. 칸반·목록별 보기와 새로고침 후 완료 상태, 완료 모음·휴지통 복원을 확인합니다.
5. 캘린더 일간·주간·월간 전환, 일정 편집, 시간 블록 선택을 확인합니다.
6. 설정의 목록 이름·색상 변경, 변경 취소·저장과 관련 계획 반영을 확인합니다.

## 이번에 유지한 영역

`src/index.css`는 뒤쪽 규칙이 앞쪽 기본값과 반응형 스타일을 덮어쓰는 구조입니다. 스타일 순서 변경을 구조 리팩터링과 섞지 않고 파일·선언 순서를 유지했습니다. UI 재설계, 목 데이터를 실제 서비스로 바꾸는 작업, 패키지·빌드 설정 변경은 포함하지 않습니다.
