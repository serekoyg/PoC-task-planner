# 하루 디자인 시스템 기초

PR #60의 미사용 코드·스타일 정리에 이어, 화면별로 반복되던 시각 규칙을 한곳에서 관리하기 위한 최소 디자인 시스템입니다. 기능과 사용자 흐름은 유지하고 표현 계층만 정리하는 것을 원칙으로 합니다.

## 조사 결과

- `src/index.css`에 기능 추가 순서대로 스타일이 누적되어 공통 규칙과 화면별 예외가 섞여 있었습니다.
- 페이지 헤더, 보기 전환 탭, 주요 버튼, 카드가 같은 역할인데도 화면마다 별도 선택자와 수치를 사용했습니다.
- 설정 화면은 별도 주황 강조색을 사용해 캘린더·할 일·모임의 파란 계열 강조색과 단절되어 있었습니다.
- 간격, 모서리, 그림자, 컨트롤 높이, 상태 색상이 원시 값으로 반복되어 일괄 조정이 어려웠습니다.
- 일부 보조 문구와 컨트롤이 지나치게 작아 화면 밀도가 높고 조작 영역이 좁아 보였습니다.

## 구조

### 토큰

`src/design-system/tokens.css`가 색상, 간격, 모서리, 그림자, 컨트롤 높이, 전환 속도와 기존 호환 별칭을 관리합니다.

- 원시 팔레트: `--color-*`
- 의미 토큰: `--surface`, `--text`, `--accent`, `--danger`, `--success`
- 공간과 형태: `--space-*`, `--radius-*`, `--shadow-*`
- 인터랙션: `--control-height-*`, `--focus-ring`, `--transition-fast`

화면 CSS에서는 원시 색상보다 의미 토큰을 우선합니다. 프로젝트별 사용자 지정 색상처럼 도메인 데이터에 해당하는 값은 예외로 둡니다.

### 컴포넌트

`src/design-system/`의 컴포넌트는 DOM 의미와 이벤트를 그대로 전달합니다.

- `Button`, `ButtonLink`: 현재 화면에서 사용하는 크기와 `primary`, `secondary` 상태를 공유합니다.
- `SegmentedControl`: 캘린더·할 일·모임의 보기 전환 동작과 접근성 상태를 공유합니다.
- `PageToolbar`: 페이지 제목, 설명, 액션의 반응형 배치를 공유합니다.
- `Surface`: 카드와 요약 패널의 표면 스타일을 공유합니다.

## CSS 단순화 기준

1. 공통 시각 규칙은 토큰 또는 디자인 시스템 컴포넌트에 둡니다.
2. 화면 CSS는 레이아웃과 해당 기능에만 필요한 상태 표현을 담당합니다.
3. 새 화면 전용 버튼·탭·카드 선택자를 만들기 전에 기존 컴포넌트의 variant로 표현 가능한지 확인합니다.
4. 같은 선언이 세 곳 이상 반복되면 공통 컴포넌트나 의미 토큰으로 승격합니다.
5. 달력 그리드, 시간표 좌표, 드래그 선택처럼 도메인 고유 표현은 억지로 공통화하지 않습니다.
6. 기능 리팩터링과 시각 리팩터링을 분리하고, 주요 경로의 DOM 의미와 상호작용을 브라우저에서 회귀 확인합니다.

## 기능 보존 체크

- 캘린더 일간·주간·월간 보기 전환
- 새 일정 편집 패널 열기·닫기
- 할 일 날짜별·칸반·목록별 보기 전환
- 새 계획 편집 패널 열기·닫기
- 모임 전체·내 모임 필터 전환
- 모임 만들기 패널 열기·닫기
- 설정 카테고리와 공개 범위 폼 표시
- 데스크톱·모바일 반응형 배치

이후 화면을 정리할 때는 위 체크를 유지하면서 `index.css`의 화면별 버튼·탭·표면 선언을 같은 컴포넌트로 점진적으로 옮깁니다.
